Three timing concepts, and they never substitute for one another

Wall-clock elapsed is how long the window stayed open. Observed active time is the producer's union of assistant and tool intervals across main and child sessions, with overlapping and nested work counted once — assistant_elapsed_ms and tool_elapsed_ms legitimately overlap and are never added. Human effort is never captured and never inferred. Active time is busy wall time; it is not human effort, not CPU time, not utilization and not additive compute.

Harnesses with no normalized producer

Phase effort telemetry unsupported for this harness — claude-code

No Claude adapter emits the normalized schema yet, so there is nothing to render for Claude Code phase executions on this axis. This is a data gap, which is a different fact from a harness that ran and spent nothing — it is never rendered as 0 and never as an empty measured figure. Two of the connected repositories are affected.
